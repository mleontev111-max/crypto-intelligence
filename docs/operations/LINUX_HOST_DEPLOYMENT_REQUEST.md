## Запрос на подготовку Linux-хоста под сервис Crypto Intelligence

### Коротко, что нужно

1. Docker Engine + плагин `docker compose`, **включённый в автозапуск** (`systemctl enable --now docker`).
2. Отдельный непривилегированный сервисный пользователь.
3. ~20 ГБ дискового пространства под два Docker-тома.
4. Исходящий HTTPS к двум доменам.
5. Входящих портов — **ноль**.

---

### Что это за сервис (чтобы понимать профиль риска)

Исследовательский сервис сбора публичных рыночных и макроэкономических данных.

- Делает **только HTTPS GET** к двум публичным источникам:
  - `api.exchange.coinbase.com` — публичные часовые свечи BTC-USD;
  - `api.stlouisfed.org` — две серии доходностей казначейских облигаций США (DGS2, DGS10) от ФРС.
- **Никакой торговли**: ни ордеров, ни переводов, ни аккаунтных или авторизованных эндпоинтов бирж. Ограничение зашито в код: транспорт разрешает только схему `https` и только эти два хоста (`ALLOWED_HOSTS` в `src/transport/read_only_http.py`), любой другой адрес приводит к ошибке. Покрыто автотестами.
- Пишет только в собственную PostgreSQL (в контейнере) и в собственный том с файлами.
- **Не принимает входящих соединений вообще.**

---

### Требования по пунктам

#### 1. Docker

- Docker Engine (не Docker Desktop) + `docker compose` v2.
- **`systemctl enable --now docker`** — это ключевой пункт всего запроса. Контейнеры описаны с политикой `restart: unless-stopped`, поэтому при живом демоне весь стек поднимается сам после перезагрузки. Именно этого нам не хватает на текущем хосте.
- Версия: любая актуальная. Стек проверялся на Docker 29.x / Compose v2 (v5.4.0).

#### 2. Пользователь и права

- Отдельный сервисный пользователь (например, `crypto`), **не root**.
- Предпочтительно rootless Docker. Если это неудобно — достаточно пользователя в группе `docker`.
- Каталог развёртывания с доступом только для этого пользователя.

#### 3. Диск

Замеренные факты по текущему объёму данных (не оценка, а фактический замер на работающем стенде):

- средний размер одного RAW-ответа: **647 байт**;
- размер базы: **8 МБ** при 40 наблюдениях.

Прогноз роста при планируемом каденсе (Coinbase раз в час, FRED раз в сутки): **менее 100 МБ в год**.

Просим выделить **20 ГБ** — с большим запасом на расширение состава источников в следующих фазах проекта, чтобы не заводить новый тикет через полгода.

Нужны два именованных Docker-тома:

- `postgres_data` — данные PostgreSQL;
- `raw_data` — неизменяемые исходные ответы источников.

#### 4. Сеть

**Исходящий** HTTPS (порт 443) нужен только к:

- `api.exchange.coinbase.com`
- `api.stlouisfed.org`

Дополнительно, **только на время сборки образа** (можно закрыть после развёртывания, если у вас так принято): `registry-1.docker.io`, `auth.docker.io`, `production.cloudflare.docker.com`, `pypi.org`, `files.pythonhosted.org`.

**Входящие порты не нужны вообще.** PostgreSQL слушает только внутри docker-сети и наружу не публикуется — в `compose.yml` секции `ports:` нет ни у одного сервиса.

#### 5. Секрет

Секрет ровно один: API-ключ FRED (бесплатный, выдаётся мгновенно, данные публичные — но это всё-таки ключ).

- Живёт в файле `.env` в каталоге развёртывания, режим `600`, владелец — сервисный пользователь.
- В git не попадает (внесён в `.gitignore`).
- **Вопрос:** есть ли у вас предпочтительное хранилище секретов (vault, ansible-vault, что-то ещё)? Готовы подстроиться под ваш стандарт.

#### 6. Резервное копирование

Неизменяемость исходных данных и возможность восстановить историческое состояние — принципиальное требование проекта, поэтому просим включить в регулярный бэкап оба тома:

- `postgres_data`
- `raw_data`

Ежесуточной частоты достаточно.

#### 7. Доступ для нас

Нужен SSH-доступ под сервисным пользователем для:

- первичного развёртывания и накатки миграций БД;
- ручных проверок (чтение счётчиков в базе);
- обновления кода (`git pull` + `docker compose build`).

---

### Что от вас **не** требуется

- **Не нужно** настраивать cron или systemd-таймеры под наши задачи — планировщик будет внутри нашего compose-стека, отдельным контейнером с `restart: unless-stopped`. От вас нужен только автозапуск самого Docker.
- **Не нужен** веб-сервер, реверс-прокси, TLS-сертификаты — сервис наружу не смотрит.
- **Не нужна** СУБД на хосте — PostgreSQL идёт контейнером в составе нашего стека.

---

### Меры безопасности с нашей стороны

Мы со своей стороны обеспечиваем:

- контейнер коллектора работает от непривилегированного пользователя (сейчас в `Dockerfile` нет директивы `USER`, контейнер запускается от root — **это будет исправлено до переезда**);
- `no-new-privileges`, отброшенные лишние capabilities, никакого `privileged`;
- никаких монтирований каталогов хоста, кроме собственных именованных томов;
- программное ограничение транспорта: только HTTPS и только два разрешённых хоста, с покрытием тестами;
- секрет не попадает ни в логи, ни в сохраняемые метаданные (ключ FRED маскируется как `REDACTED` в выводе — проверено).
